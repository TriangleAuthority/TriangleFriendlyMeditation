# Meditation in 5.x

How 5.x (build 1090142, `vanilla-5.x`) differs from 1.32 in everything Friendly Meditation changes, and the proposed 5.x form of each change. Read from the files (`git diff -w vanilla-1.32 vanilla-5.x`, the 5.x install's config files), **unverified** in game. Annotation rules are TriangleGhostMode's (`docs/development.md`, "Annotations" and "Choosing a technique").

## Summary

- **5.x reworked meditation itself.** Pressing N (or choosing Meditation in the radial menu) sits Geralt down in the world, turns him toward open space, and opens the clock menu over the rendered world in slow motion; choosing an hour plays a time-lapse in the world (game time scale up to 5 plus raised hours per minute, foliage and clouds sped up, weather changes), then `MeditationRestoring` as in 1.32. Moving or jumping stands him up. **5.x has no real-time meditation:** it is still 1.32's model (choose an hour, the time passes quickly, then `MeditationRestoring` heals and simulates the buffs at once), presented in the world. N, the radial menu (`OnRadialMenuItemChoose("Meditation")`) and the panels' Meditation tab all go through `Meditate()` and the clock (the tab: the clock's `OnMeditate` calls `Meditate()` then `MeditationWait`). The owner saw meditation from the radial menu play like 1.32's (2026-11-13), as the scripts predict. So 5.x already has only the presentation part of what FM added (no menu hiding the world, Geralt sitting in place); it does **not** have FM's hotkey meditation without the menu, the open-ended fast-forward, buffs running in accelerated time instead of the end-of-wait simulation, the camera options or the campfire.
- **Every function FM touches still exists**, except that FM's own helpers (`IsMeditating`, `ModStartMeditation`, ...) do not collide with any 5.x name. The three state files, the clock menu and the common menu changed a lot; the bed and the place of power now contain CDPR's own version of FM's two fixes.
- **No 5.x auto-refill or real-time setting.** The hidden option group `RemasterCombat` (sub-group `RemasterMeditation`, `visibilityCondition="hideAlways"` in `gameplay.xml`) holds 5.x's time-lapse parameters: `MeditationBlendTime`, `MeditationBlendStepCount`, `MeditationWaitTime`, `MeditationWaitTimeAddPerHour`, `MeditationMaxTimescale`, `MeditationMaxFoliageTimescale`, `MeditationMaxCloudsTimescale`, `MeditationBlendOutHpmTarget`, read by `MeditationWaiting.OnEnterState`. Refill is still `SingletonItemsRefillAmmo()` inside `MeditationRestoring` (Ghost Mode's CRAFT-07 alcohol rule applies there).
- **Hotkeys still work the legacy way** (input.xml + input.settings); 5.x added no script or mod API for bindings. See [Hotkeys on 5.x](#hotkeys-on-5x).

## Effects in accelerated time

- 5.x's own waiting already speeds the engine up (time scale up to 5, which runs timers and effects faster in real time) and then calls `MeditationRestoring(realSecondsPassed)` → `SimulateBuffTimePassing`. FM's `PerformUpdate(realTimeSecs × acceleration)` per tick instead feeds the effect manager steps of up to several seconds (at 60 game minutes per second and the default rate, about 240× normal: roughly 4 s of effect time per frame at 60 fps; unverified estimate). Any per-tick effect code (Ghost Mode's regeneration, toxicity, exhaustion, decoction effects) then sees large `deltaTime` values.
- `ConvertGameSecondsToRealTimeSeconds` divides by the **current** hours per minute (`engine/gameTime.ws`), so FM's step is the real time elapsed × the acceleration, i.e. the normal-speed time that passed. The engine's normal effect tick runs in addition (a small over-count, about 1/acceleration).
- `SimulateBuffTimePassing` in `W3PlayerWitcher` (5.x) calls `FinishQuen(true)`; FM's path never calls it, which may be why FM added `W3Effect_BasicQuen.OnEffectRemoved`.

## What slice 1 showed

**Verified** 2026-11-15 (beside Ghost Mode, by scripted calls):

- **Sitting down without the clock:** in 5.x's `Meditation` state, `OpenUI` is called once Geralt is seated (from the anim event `OpenUI`, about 2 s after `Meditate()`) and again when `Meditate()` runs while he sits; skipping it in a wrapper leaves him seated with no menu (`PEA_Meditation`).
- **5.x's sit-down switches the input context to `Meditation`**, a context no input file defines. A wrapper of the state's `OnPlayerTickTimer` can switch back (`theInput.RestoreContext('Meditation', false)`) and clear the state's private `changedContext` (a wrapper sees the state's private variables), so 5.x restores nothing when he stands up.
- **The fast-forward:** `theGame.SetHoursPerMinute` with `GetFastForwardSystem().BeginFastForward()` works from the player tick while the state idles; normal speed is 0.25 hours per minute.
- **Legacy's effect formula gives effects exactly the game time that passed:** `PerformUpdate(ConvertGameSecondsToRealTimeSeconds(gameSecs) * hpm / storedHpm)` summed to game seconds / 15 (33,500 game s → 2,233 s of effects). The engine's own per-frame update comes on top (real time, small).
- **Stops:** `MeditationForceAbort` (what a hit and the start of combat call) and a real fight both reach the state's `StopRequested`; Geralt stands up through 5.x's `StopMeditation`.

## Hotkeys on 5.x

What the 5.x files show (**unverified** in game unless stated):

- **Bindings live in `Documents\The Witcher 3\input.settings`**, still a plain-text file with one `[Context]` section per input context (seen on the owner's machine: `[Exploration]`, `[BASE_PanelsShortcuts]`, ... and `[InputSettings] Version=60`). The defaults come from `<game>\bin\config\r4game\legacy\base\input_qwerty.ini` (`_azerty`, `_qwertz`; plus `override_input_switch2.ini`), not from the mod. 5.x still uses the `State=Duration,IdleTime=` hold syntax (Gallop, the new `DrinkPotion1Hold`–`4Hold`), the same trick FM's `HoldToMeditate` uses.
- **The Key Bindings menu** is built from `<game>\bin\config\r4game\user_config_matrix\pc\input.xml` (`Group id="PCInput" builder="Input"`, UTF-8 with BOM in 5.x). 5.x's `input.xml` added photo mode, the potion hold variants, oil keys and `BuryBody`; FM's legacy file is 1.32's and cannot be copied over it.
- **No script API** adds a binding: `CInputManager` (`game/inputManager.ws`) can register listeners, switch contexts and read keys (`GetPCKeysForAction`, `GetLastActivationTime`, `IsActionActivatedWithPattern`), but not bind.
- **mod.io does not allow custom inputs** (or menus), per the mod.io guide TGM cites; FM is a PC mod in the `mods` folder either way.
- **Ghost Mode has no hotkeys**, so TGM's docs and tools have nothing on bindings; `build_mod.py` installs menu XML only.

Options for the port:

1. **Legacy way:** add FM's `Var` entries to 5.x's `input.xml` (whole-file edit of a game config file, outside the mod folder, colliding with any other mod that does the same) and the `input.settings` lines (the player pastes them, or `build_mod.py --install` adds and records them as it does menu files). Most likely to work; worst for coexistence.
2. **Own XML file:** a `modFriendlyMeditationInput.xml` in `user_config_matrix\pc\` with a `builder="Input"` group. The game reads every XML there, and groups of one id can come from two files (5.x's `Hidden` group is in `hidden.xml`; legacy FM added a second `Hidden` group inside `input.xml`), so a second `PCInput` group may merge into Key Bindings. Untested. Bindings would still need the `input.settings` lines.
3. **No new action (fallback):** detect a long press of vanilla's `PanelMeditation` (N) in a `@replaceMethod` of `OnCommPanelMeditation` (press time stored, a timer at 0.4 s starts FM meditation, a short release keeps 5.x's behaviour). Covers the main hotkey without any config edit; the fast-forward and campfire keys would need another vanilla action or menu options instead. Untested.

**Slice 0 results** (**verified** 2026-11-15, `ToggleSpawnCampFire` on End, by scripted calls):

- **An `input.settings` line alone binds an action:** `IK_End=(Action=ToggleSpawnCampFire)` under `[Exploration]` makes `theInput.GetPCKeysForAction` return `IK_End`, with no `input.xml` entry. 5.x keeps lines it does not know when it rewrites the file on exit (the line stayed in its section).
- **Option 2 does not work:** a second `PCInput` group in an own XML file is ignored (the group keeps vanilla's 56 entries), and the Key Bindings screen reads only `PCInput` (`CR4IngameMenu.GetKeybindGroupTag` names it).
- **Option 1 works:** the legacy `Var` line pasted into the `PCInput` group of the game's `input.xml` puts the action in Key Bindings (57 entries); its display name `ToggleSpawnCampFire` is translated by FM's string of that key. The port ships option 1 as instructions (`release/input.xml.part.txt`), as legacy did. Manual setup is accepted (owner, 2026-11-14).
- **Scripts register a new action like a vanilla one:** a calling wrapper of `CPlayerInput.Initialize` adds `RegisterListener(this, 'OnToggleSpawnCampFire', 'ToggleSpawnCampFire')`, and an `@addMethod` event handles it.

## What is hard

1. **Coexisting with 5.x's reworked meditation.** FM must either take over the vanilla states (wrappers that skip `wrappedMethod`, or `@replaceMethod` of their events) or run beside them with a flag. Both states' latent loops, `m_had_meditation` checks in the camera and `InitState`, the common menu's `MeditationLock` pause, the clock's time scale 0.1 and `CloseUI`/`HideClockMenu` all assume 5.x's flow.
2. **Hotkeys** (above): no supported mod path; needs a probe before anything else.
3. **Wrappers that skip the vanilla body** also skip every wrapper further in the chain, including other mods' (Ghost Mode's, Preparations'); the chain order between blobs follows mod priority (unverified). `@replaceMethod` has the opposite problem (one mod wins).
4. **Preparations' contract** is shared field and method names on `W3PlayerWitcher`, which two separately compiled blobs cannot both declare ([port-plan.md](ghost-mode-compatibility.md#preparations-interaction)).
5. **Large effect steps** through `PerformUpdate` against Ghost Mode's per-tick effect code.
6. **Behaviour graph:** FM drives `MeditateWithIgnite`, `HasCampfire`, `MeditateAbort` and `PEA_Meditation` without vanilla's anim-event flow; 5.x's graph may have changed (5.x added the `AllowRotation` and `OpenUI` events). Only the game shows it.
